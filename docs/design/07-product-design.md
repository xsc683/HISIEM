# Phase 4 产品设计 — 用户接入与解析规则管理(SIEM 产品化)

> 状态:产品设计稿 · 2026-08-16
> 本文档是**产品层**设计(用户角色、体验流程、功能模块、竞品对标),与 [06-user-onboarding.md](06-user-onboarding.md) 的**技术层**设计互补。
> 参考业界成功产品在"日志接入 / 解析规则管理"上的产品与 UX 模式。

## 1. 产品定位

**一句话定位**:HISIEM 是一个轻量级 SIEM,本文档设计其**管理控制台**——让安全工程师能自助地把新日志源接入系统、管理解析规则,而不是改配置文件。

**解决的核心问题**:
- 现在加一个数据源 = 手改 `logstash.conf`(grok 模式/ECS 字段/时间解析)→ 门槛高、不可复用、无测试、无监控。
- 产品目标是:把"接入日志"从**改配置**变成**点几下**。

**产品形态**:Web 管理控制台(与 Kibana 检测看板分工:控制台管"接入/解析/检测规则/告警三线(产品方向)",Kibana 管"事件检索(Discover)/检测看板/深度调查")。

## 2. 目标用户与角色(personas)

| 角色 | console 角色 | 典型场景 | 痛点 | 成功指标 | 权限边界 |
| --- | --- | --- | --- | --- | --- |
| **安全管理员** | `admin` | ① 周五临时新增防火墙日志源,走 5 步向导接入;② 为常见设备建/维护解析模板(ssh-auth/nginx-access);③ 处理失败率高的源(补模板或下线) | 加源 = 手改 `logstash.conf`(grok/ECS/时间解析),门槛高、易错;模板散落不复用;解析失败无提示 | 新增源接入时长 **≤10min(端到端)且无需开发介入**;模板库命中率(选到即用)≥90%;新源 24h 内失败率 <5% | 建/删数据源、创建/修改/晋升/降级模板、查看健康与失败详情、启停检测规则;用户角色管理(P2) |
| **运维/采集工程师** | `ops` | ① 部署采集端点(开端口/挂目录),确认日志流入;② 盯数据健康,处理停采/失败率突升;③ 停用/释放不再使用的源 | 连通断了不知情;端口被占/重复无提示;日志量异常无视图 | 配置端点到看到事件流入 ≤10min;健康页 15min 内发现停采;失败率突升可见可下钻 | **写**数据源(创建/配端点/停用/删除)、看健康;**不可改模板、不可改规则** |
| **安全分析师** | `analyst` | ① 确认数据源完整、不丢日志;② 下钻失败日志判断"格式变了还是模板没覆盖";③ 报解析问题给管理员 | 数据不完整会漏检;失败原因看不懂 | 该源数据完整率(无缺/无静默丢);一次下钻定位失败根因(格式变更/模板缺口) | **只读**健康/数据源/失败下钻;**不可建源、不可改模板** |
| **审计员** | `audit` | ① 抽查谁创建/修改了数据源与模板;② 核对生效/停用操作留痕;③ 检查最小权限合规 | 操作无留痕,说不清 who/when/what;审计无材料 | 全部 activate/配置生成/停用操作有审计日志,可检索、可导出(CSV) | **只读**(健康 + 审计日志 + 数据源/模板只读);不可写任何配置 |

> 设计取舍:**接入层面向"管理员/运维"**,不做分析师那套告警调查(那是 Kibana + 检测层的活;4.0 过渡,控制台告警台 P1 落地)。
> 权限边界 = **console 应用层**最小权限;同一账号"控制台能做什么"与"Kibana 能查什么"是两套独立授权,完整角色映射见 §5.3([security-rbac.md](security-rbac.md) 对齐)。

## 3. 竞品对标(产品 / UX 层面)

| 产品 | 接入与解析的产品做法 | 可照搬的 UX 机制(具体交互) | 借鉴点 |
| --- | --- | --- | --- |
| **Splunk** | `Add Data` 向导(选择数据源类型 → 上传/配置 → 识别 sourcetype);`sourcetype` 是解析的"钥匙",字段提取在 search-time 配置 | **粘贴样例 → sourcetype 置信度识别**(按相似度推荐,而非手填)→ 解析预览 → 时间格式一键覆盖(识别失败可手改) | **向导式接入**;解析按"源类型"组织 |
| **QRadar** | `Log Source` 管理(加日志源 → 选 DSM → 自动识别);**DSM Editor 基于样例事件可视化提取字段**(粘贴日志 → 定义字段 → 看结果) | 样例中**高亮可提取字段 → 拖拽/点选映射到属性**,可视化定义字段而非写正则 | **自动识别日志源**;基于样例的可视化字段提取 |
| **Elastic** | Fleet + **Integrations 市场**(选集成包 → 部署 Agent → 自动采集解析);`Custom Logs` 支持自定义 | **集成目录一键安装**(选集成 → 装 Agent → 自动采集解析)+ **simulate 测试**(上线前离线跑样例验证管道) | **模板/集成市场**;打包化"选即用" |
| **Cribl** | **Onboarding 流程**(选 Pack → 样例测试 → 路由);**unknown 桶兜底**(未知格式不丢,事后补解析);数据源文档化;健康监控 | **Pack 沙箱跑真实样例**(离线验证解析)→ 未知格式进 **unknown 桶**(不静默丢,事后补解析) | **样例测试**;未知兜底;数据源文档化+监控 |
| **Sentinel** | **Data Collection Rule(DCR)**:声明式"表 + 解析 + 转换" | **声明式"表 + 解析 + 转换"**(表结构固定,解析/转换是声明而非脚本) | 声明式接入规则 |

**本产品照搬的机制**(对应 §4 落地):
- Splunk 的「粘贴样例 → 置信度识别 → 预览」→ 接入向导第 ④ 步(发样例验证)与模板库检索
- QRadar 的「高亮 → 映射」→ 自定义解析编辑器(§4.2)
- Elastic 的「一键装集成 + simulate」→ 模板库"选即用" + 上线前 `logstash --config.test_and_exit` 校验(§4.1 第 ⑤ 步)
- Cribl 的「unknown 兜底」→ `_parsefailure` 计数与失败率可见(§4.3);`siem-events-raw-*` 兜底路由已落地
- Sentinel 的「声明式」→ 数据源 = 声明式 YAML(`infra/log-sources/*.yaml`),非手写管道

**提炼的产品 UX 共性**(本产品遵循):
1. **向导式接入**:选类型 → 配置端点 → 测试 → 生效,而不是填表单/改配置
2. **模板/规则库**:预置解析器,用户"选"而非"写"
3. **基于样例的即时反馈**:粘贴一条日志 → 立刻看到提取的字段
4. **未知兜底**:解析失败的日志进 raw 桶,可事后补规则,不静默丢
5. **数据源文档化 + 健康监控**:每个源有元信息,失败率/量可见

## 4. 核心用户旅程(UX flows)

### 4.1 接入一个数据源(主旅程)

```
① 新建数据源      ② 选解析模板       ③ 配置采集端点     ④ 发样例验证       ⑤ 生效
"接入中心"新建  从模板库选/检索  填端口/路径/IP/名称  粘贴样例→看字段预览  点"生效"
   │               │                 │              │                  │
   │            (没有合适的?→        │          (字段对→下一步;   生成配置→同步
   │             跳去自定义解析)      │           不对→回模板库换)   →日志流入→确认
   └──────────────────────────────────┴──────────────────────────────┘
```

**逐步规格**(每步 = 页面元素 / 校验规则 / 失败分支 / 成功判据):

| 步骤 | 页面元素 | 校验规则 | 失败分支 | 成功判据 |
| --- | --- | --- | --- | --- |
| ① 新建数据源 | 名称输入框、协议下拉(tcp/syslog/file)、协议说明(决定②/③端点形态) | 名称必填、≤64 字符、同协议下唯一;协议必选 | 名称重复 → 红提示"同协议下已存在同名数据源",不进入下一步 | 名称+协议已填且校验通过,可进入② |
| ② 选解析模板 | 模板库检索框(`q=关键词/协议`)、模板卡片列表(名称/协议/状态)、详情浮层 | 所选模板 id 存在且 `status != deprecated` | 库为空/检索无结果 → 空态引导"去模板库建模板或自定义解析";选到 deprecated → 置灰禁选 | 已选一个可用模板,卡片高亮 |
| ③ 配置采集端点 | 按协议切换:tcp=端口;syslog=端口+格式;file=路径;附日志源标识(系统生成 `log.source_id`/`log.source_name`) | 端口为整数 1-65535 且**未被其他数据源占用**(后端查 `infra/log-sources/*.yaml`);file 路径存在可写 | **端口冲突 → 红提示"端口 5001 已被数据源 ssh-web-01 占用",不落库**;路径不存在 → 红提示 | 端点参数校验通过,可进入④ |
| ④ 发样例验证 | 样例粘贴框(单条 ≤8KB)、"测试解析"按钮、字段预览表、解析结果状态 | 样例非空;调 `POST /api/parser-templates/test` | **解析失败(未匹配)→ 红提示 + 两个分支按钮:「回模板库换」/「自定义解析」**(跳 §4.2),不进入生效 | `ok=true` 且模板 expect 关键字段全部命中 |
| ⑤ 生效 | 配置摘要(模板/端点/生成片段)、"生效"按钮、同步任务进度(轮询 `tasks/{taskId}`)、错误日志 | ①-④ 全部通过;生成配置先过 `logstash --config.test_and_exit` 校验 | **同步失败 → 状态=failed,保留旧配置(可回滚),展示校验日志,按钮变「重试」**;校验失败 → 不 reload,旧配置继续生效 | 配置生成+同步+reload 成功,状态=已生效,跳转该源健康页 |

**每一步的交互反馈**:向导右侧常驻"字段预览"面板;生效后跳转到该数据源的健康页(最近 1 小时事件量、解析失败率)。
第 ⑤ 步为**异步**(202 + taskId):因含 rsync + `--config.test_and_exit` 校验 + reload/重启,耗时通常 >3s,前端轮询任务状态,状态机按任务结果迁移(story-01 §5.2)。

### 4.2 自定义解析规则(次旅程)

```
① 入口:模板库找不到 → "自定义解析"
② 粘贴一条样例日志
③ 编写/微调 grok 模式(自动补常用模式片段,实时校验)
④ 即时预览:提取字段 + 解析成功/失败
⑤ 补 ECS 字段/actions(成功/失败等)→ 填正负样本
⑥ 保存为模板(experimental)→ 可复用
```

**编辑器布局**(左样例 / 右预览):

```
┌─────────────────────────────────────────────────────┐
│ ① 模板元信息(id/name/protocol/ecs 固定字段)          │
├─────────────────────────────┬───────────────────────┤
│ 样例输入(左,可多行)         │ 字段预览(右)          │
│ 每行 = 一条样本             │ 提取字段表 + 成功/失败 │
├─────────────────────────────┴───────────────────────┤
│ ② grok 模式编辑框 + 常用片段提示(下方抽屉式清单)     │
├─────────────────────────────────────────────────────┤
│ ③ 测试样本管理:正样本/负样本列表(添加/删除/导入/导出)│
└─────────────────────────────────────────────────────┘
```

**grok 常用模式片段提示清单**(与 java-grok 对齐):

| 类别 | 片段 |
| --- | --- |
| 用户/主机 | `USERNAME`、`HOSTNAME`、`PROG`、`WORD` |
| 网络 | `IP`、`IPV4`、`IPV6`、`MAC`、`HOSTPORT` |
| 时间 | `SYSLOGTIMESTAMP`、`TIMESTAMP_ISO8601`、`TIME`、`MONTH`、`MONTHDAY`、`YEAR` |
| 数字 | `NUMBER`、`INT`、`BASE10NUM` |
| 通用 | `DATA`、`GREEDYDATA`、`NOTSPACE`、`PATH`、`URIPATH` |
| 复合 | `COMMONAPACHELOG`、`COMBINEDAPACHELOG` |

**实时校验**:输入 debounce 300ms 后调 `POST /api/parser-templates/test`;后端 grok 编译结果缓存(同模式不重复编译),**P95 <500ms**;超时显示"解析中"骨架,不阻塞输入。

**测试样本管理**:
- 正样本:应成功解析且字段与 `expect` 一致;负样本:应明确不匹配(验证"不会误解析其它格式")。
- 每样本单条 ≤8KB;样本集 ≤100 条;支持批量粘贴导入与导出 YAML。
- 保存门禁:**正负样本全部通过才允许保存**(任一未过 → 拒绝保存,文案:"存在未通过的正样本或负样本,请修正 grok 模式后重试")。

**experimental → stable 晋升**:新建模板一律 `experimental`;满足晋升条件后可"提交晋升"(见 §4.4)。

### 4.3 数据源健康监控

**指标口径**(按 `log.source_id` 聚合,与 [story-05](../story/story-05-data-health.md) 一致):

| 指标 | 口径 | 判定 |
| --- | --- | --- |
| 事件量 | 近 1h / 近 24h 该源事件数 | — |
| **失败率** | **近 1h 该源 `tags=_parsefailure` 事件数 / 该源事件总数** ×100% | — |
| 最后收到时间 lastSeen | 该源最近事件 `@timestamp` | **停采判定**:超过 2× 该源正常到达间隔(默认 15min)无新事件 → 卡片异常 |
| **失败率突升** | 本 1h 失败率 / 前一 1h 失败率 | **本 1h 失败率 >5% 或 本 1h/前一 1h 环比 ≥2×**,且**本 1h 失败事件数 ≥20** → 高亮;失败事件数 <20 视为样本过小**豁免**(不判定) |
| 趋势 | date_histogram(24h, 1h bucket) 折线 | — |

> **阈值可配置性**:上表失败率突升 / 停采判定阈值为**默认阈值(U1 口径)**,用户可配置(系统设置,对齐 08 §5.0 横切原则);当前先落默认,配置 UI 后置。

**失败下钻**:点失败率高的卡片 → 最近失败日志列表(默认 50 条),每行展示**原文(`event.original` 未解析行,产品口径即 `event.raw`)+ 时间 + 来源**;可"复制原文到自定义解析"(跳 §4.2 一键补模板),决定"补模板 / 调采集 / 该源下线"。

> 当前 `_parsefailure` 事件带原文并路由到 `siem-events-raw-*`;未知桶不进入 Kafka/Flink，健康页可按源下钻查看。

### 4.4 模板生命周期(experimental → stable → deprecated)

```
experimental ──晋升──▶ stable ──降级──▶ deprecated ──确认无依赖──▶ 删除
     ▲                   │                    │
     └──未达条件退回──────┘                    └──回炉(转回 experimental)
```

**状态机与条件**:

| 状态 | 进入条件 | 可做什么 | 不允许 |
| --- | --- | --- | --- |
| `experimental`(新建默认) | 正负样本通过即可保存 | 可被接入向导选用;卡片标注"实验性" | 不可标记"稳定" |
| `stable` | **① 正负样本全部通过(一键重跑)② 挂载 ≥1 个数据源且观察 ≥7 天 ③ 观察期该源解析失败率 <5% 且无新增未覆盖变体** | 全功能;作为默认推荐 | 未达条件不可晋升 |
| `deprecated` | ① 挂载源失败率持续 >5%(连续 3 个 1h 窗口)② 或有新模板替代 | 保留已挂源继续解析(不中断) | 禁止新数据源选择(卡片置灰,标注"将停用") |
| 删除 | deprecated 保持 ≥30 天且无源依赖 | 物理删除(或转回 experimental 回炉) | — |

**模板被改对已挂数据源的影响**(改模板 = 影响所有挂载它的源):

```
保存新版本 ─▶ 检测受影响源(挂了该模板的全部数据源)─▶ 标记受影响源(状态=待重验,健康页横幅)
    │                                                     │
    └─▶ 重跑样本(正负样本)─▶ 批量重验(取各受影响源最近真实样例)
           │                                                │
           ├─ 全过 ─▶ 发布(重新生成配置 → 校验 → reload)─▶ 受影响源自动更新,横幅消除
           └─ 有失败 ─▶ 阻止发布(降级回 experimental / 保持旧配置),受影响源继续用旧配置,不自动切换
```

- 发布失败/重验失败时**旧配置不受影响**(沿用"校验通过才 reload"原则,story-01 FR-3)。
- 受影响源健康页显示"模板已更新,待重新生效"横幅,点击可手动重新生效。

### 4.5 数据源下线 / 停用

```
① 发起停用 ─▶ ② 确认影响(弹窗:该源将停止采集,历史数据保留)─▶ ③ 移除 input + 释放端口
   ─▶ ④ 状态=停用 ─▶ ⑤ 数据健康保留历史记录(归档视图),可重新启用
```

| 操作 | 做什么 | 保留什么 | 注意 |
| --- | --- | --- | --- |
| **停用** | 移除该源 input、释放端口,状态=停用 | 数据源记录、历史事件(ES 由 ILM 365d 管理)、健康历史 | 重新启用 = 重新生成 input(原端口空闲可复用,否则换新端口);不删配置模板 |
| **删除** | 重新生成不含该 input 的配置 + 释放端口,物理删除记录 | 历史事件保留(不随源删除) | 二次确认"删除后不可恢复,历史事件仍保留";关联的模板不删 |

- 停用/删除均为异步生效任务(202 + taskId,复用 activate 的同步链路),状态按任务结果迁移(story-01 §5.1 状态机)。
- 停用/删除写入审计日志(§5.3)。

## 5. 产品信息架构(功能模块)

```
管理控制台
├── 接入中心          ← 新建数据源(向导)、我的数据源列表
├── 解析规则库        ← 预置模板浏览/检索、自定义解析、模板详情/测试
├── 数据源管理        ← 数据源 CRUD、采集端点、关联模板
├── 数据健康          ← 各源事件量/失败率/未知日志、趋势
└── 设置              ← 资产关键度、ES/存储状态、审计日志、(后续)用户与权限
```

### 5.1 页面 / 路由清单(控制台接入侧)

### 5.2 表单与校验规格

| 字段 | 校验规则 | 错误提示 / 错误码 |
| --- | --- | --- |
| 数据源名称 | 必填、≤64 字符、同协议下唯一;字符集 `[a-zA-Z0-9-_]` | "名称不能为空" / "名称过长(≤64 字符)" / "同协议下已存在同名数据源" |
| 协议 | 必选,tcp/syslog/file | "请选择协议" |
| 采集端口 | 整数 **1-65535**;且未被其他数据源占用 | "端口需在 1-65535 之间" / "端口 5001 已被数据源 ssh-web-01 占用" |
| 文件路径 | file 协议必填、路径存在可写 | "路径不存在或不可写" |
| 模板 id | 必填;格式 `<vendor>-<type>-<seq>`(如 `nginx-access-001`);**全库唯一**;同名 vendor+type 覆盖需二次确认 | "模板 id 格式应为 vendor-type-seq" / "模板 id 已存在,确认覆盖?" |
| grok 模式 | 编译校验(java-grok) | `GROK_001` 语法错误(含位置) |
| 样例日志 | 单条 ≤8KB(粘贴测试);编辑器样本每条 ≤8KB、样本集 ≤100 条 | "样例超出 8KB 限制" / "样本集超出 100 条" |

**grok 错误码**:

| 错误码 | 场景 | 提示文案 |
| --- | --- | --- |
| `GROK_001` | grok 模式编译失败(语法错误/引用了不存在的模式名) | "grok 语法错误:<位置>:<原因>" |
| `GROK_002` | 样例未匹配任何模式 | "未匹配任何 grok 模式,请检查字段与分隔符" |
| `GROK_003` | 匹配成功但时间字段无法解析 | "时间字段 <field> 无法按 formats 解析" |

### 5.3 权限与审计(P1)

**console 角色**(应用层,与 [security-rbac.md](security-rbac.md) 的 ES/Kibana 角色对齐):

| console 角色 | 接入侧能力 | 对应 security-rbac(ES/Kibana) |
| --- | --- | --- |
| `admin` | 建/删源、创建/修改/晋升/降级模板、启停规则、看健康 | 管理级(ES 初始化用 elastic,日常用 admin 角色);Kibana 空间 all |
| `ops` | 写数据源(创建/配端点/停用/删除)、看健康 | 写 `siem-events-*`(仅经生成器/采集链路);Kibana 只读或 SIEM 空间 view |
| `analyst` | 只读健康/数据源/失败下钻 | `siem_analyst`(`siem-events-*`/`siem-alerts` 只读)+ Kibana `siem_analyst_kibana` |
| `audit` | 只读健康 + 审计日志(数据源/模板只读) | 只读 + 审计索引读 |

**审计日志**(所有 `activate`/配置生成/停用/删除/模板变更操作必写):
- 字段:`who`(账号)、`when`(时间戳)、`what`(动作 + 对象 id + 前后状态/配置 diff 摘要)、`result`(成功/失败)。
- 覆盖:数据源创建/生效/停用/删除、模板创建/修改/晋升/降级/删除、规则启停。
- 存储:控制面 PostgreSQL `audit_logs` 已落地,控制台 API 可查询；ES 侧审计索引映射仍按后续需要评估。

## 6. 功能能力地图 + MVP 优先级

| 模块 | 能力 | 优先级 |
| --- | --- | --- |
| 接入中心 | 数据源向导(新建数据源/选模板/配端点/测试/生效) | **MVP** |
| 接入中心 | 数据源落库 + 生效到 Logstash(202 + taskId 异步同步) | **MVP** |
| 解析规则库 | 预置模板浏览/选择 | **MVP** |
| 解析规则库 | 自定义解析(样例 → grok → 预览 → 保存) | P1 |
| 解析规则库 | 模板生命周期(晋升/降级、模板改动影响面提示) | P1 |
| 数据源管理 | 数据源 CRUD、状态、停用/删除(释放端口) | ✅ 已实现 |
| 数据健康 | 事件量/失败率(含突升判定/下钻)/未知日志视图 | ✅ 已实现 |
| 设置 | 权限与审计(console 角色鉴权 + 审计日志) | ✅ 已实现 |
| 设置 | 资产关键度配置 | ✅ 已实现 |
| 设置 | 用户与权限(RBAC 完整管理) | ✅ 已实现 |

**MVP 定义**:安全管理员能用向导把一种新日志源接进来并真正生效(日志流入可查),且能从模板库选到 SSH 等预置模板。

### 6.1 MVP 验收口径(Given-When-Then)

**主路径**:
- **Given** 安全管理员登录控制台,从模板库选中 `ssh-auth` 模板、配采集端口 5001
- **When** 点"生效"(同步成功,状态=已生效),并向 5001 发一条 SSH 认证日志
- **Then** 日志从 5001 流入并出现在 `siem-events-*`,数据健康页该源事件量增长、解析失败率 <5%

**异常分支**:
- **Given** 端口 5001 已被其它数据源占用
- **When** 提交端点配置
- **Then** 前端红提示"端口 5001 已被数据源 X 占用",**不落库**,不产生任何配置变更

- **Given** 样例日志不匹配 `ssh-auth` 任何 grok 模式
- **When** 点"测试"
- **Then** 显示解析失败 + 「换模板 / 自定义解析」分支,不进入生效

**量化断言(MVP 上线判据)**:
- 接入一个新源端到端(向导→生效→日志流入)≤10min,且无需开发改配置;
- 生效同步失败时状态=failed、旧配置保留、可重试(不中断既有采集);
- 健康页能看到新源事件量增长与失败率(失败率 = 近 1h `_parsefailure`/总数)。

## 7. 产品形态与演化

- **当前**:Web 控制台(React) + Spring Boot API;接入层独立于 Kibana。
- **后续**:API 开放(第三方/脚本接入)、与 Kibana 检测看板导航打通。
- **与检测层分工**:控制台管"数据进得来、解析对不对、权限与处置";Kibana 管"看什么、查什么、怎么可视化";Flink 管检测。

**Phase 4 后路标**(何时做什么,与 [05-roadmap.md](05-roadmap.md) 对齐):

| 能力 | 何时做 | 触发条件 / 理由 |
| --- | --- | --- |
| 配置热加载(改文件即生效、免重启) | Phase 4 中期(P1) | 当前 reload/重启有秒级中断;多源并发接入后手动重启不可接受 |
| 多人协作 RBAC(转派/锁定/FLS) | 后置 | console 认证、四角色与基本用户管理已落地；复杂协作和多租户仍未做 |
| 开放 API / 脚本接入(`add-log-source.py` → 正式 REST) | Phase 4 后(P2) | 第三方/脚本化接入场景出现;复用 `LogSourceService` 契约 |
| 多租户(按 org/index 隔离 + FLS) | 远期 | 单租户 lab 跑通后;依赖 RBAC + ES 多租户模式(security-rbac §3) |
| siem-events-raw 未知桶路由(健康页切到 raw) | ✅ 已实现 | `_parsefailure` 路由到 `siem-events-raw-*`,不进入 Kafka/Flink |
| 模板市场 / 远程共享 | 远期 | 内部库积累稳定模板后;社区生态价值 |
| 采集 Agent(轻量转发端) | 远期 | 当前 tcp/syslog/file 输入即可覆盖 lab;远端主机采集需 Agent |
