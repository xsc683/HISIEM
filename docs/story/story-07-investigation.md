# Story 07 — 调查台·案件聚合(远期)

> **元信息**
> - 关联模块:08 产品设计 §5.5 调查台(远期)
> - 优先级:远期
> - 状态:草稿(概要)
> - 依赖:告警三线(Story 04);关联数据(related_events/实体风险)

---

## 1. 用户故事

**作为** 安全分析师,
**我希望** 把相关告警聚合成一个案件(incident),并查看攻击时间线与关联实体,
**以便** 从"一条条告警"升级为"一次攻击的完整调查"。

## 2. 背景与目标

### 2.1 背景
- 告警已带 related_events(窗口/CEP)、实体风险(IP/用户)、OCSF 视图。
- 缺:告警→案件聚合、时间线、调查工作台。

### 2.2 目标(远期)
- 相关告警自动/手动聚合为案件,案件有状态与负责人。
- 案件内看时间线 + 关联实体 + 相关原始事件。

### 2.3 非目标
- 不做 SOAR 自动化处置。
- 不做完整取证。

## 3. 用户旅程(概要)

```
① 告警台选中相关告警 → ② 聚合成案件 → ③ 案件详情(时间线/实体/原始日志) → ④ 结案
```

## 4. 需求明细(概要)

| ID | 需求 | 优先级 |
| --- | --- | --- |
| FR-1 | 告警聚合成案件(按实体/时间窗) | 远期 |
| FR-2 | 案件详情(时间线、相关告警、实体、原始事件) | 远期 |
| FR-3 | 案件生命周期(open/investigating/resolved) | 远期 |

## 5. 后端架构(概要)

```
前端(调查台) → API(/api/cases) → ES siem-cases(案件)
聚合逻辑:按实体 + 时间窗聚类(可参考 QRadar Offense / Elastic Cases)
```

## 6. 数据流实现(概要)

```
告警(related_events/实体)→ 聚合 → siem-cases → 调查台
```

## 7. 验收标准(概要)

- 相关告警可聚合成一个案件,案件内能看到时间线和关联实体。
- 案件生命周期完整,结案后可回溯。
