# Story 11：Vue 控制台与检测规则可视化编写

> 状态：已实现。当前 API/路由的权威契约仍是 [`../product-contract.md`](../product-contract.md)，本文只保留本次需求、设计原则和验收结果，不复制全部接口清单。

## 用户价值

分析师在规则列表就能理解“检查哪个字段、用什么条件、在哪个窗口达到多少次”，并通过独立详情页查看完整 DSL。管理员可以用表单创建或编辑单事件/窗口规则，保存后明确看到“待部署”，不会误以为页面保存已经改变 Flink 运行态。

控制台从 React 重构为 Vue 3 的价值不来自框架名字，而来自同时完成真实路由、模块拆分、列表/详情/表单分离、统一错误处理和按路由请求数据。

## 实现原则

- `App.vue` 只保留全局 Provider 和 Router 出口，布局、请求、认证和业务页面各自分层。
- `vue-router` 提供规则、告警、案件、数据源、关键度和用户的可深链详情/表单。
- `infra/rules/*.yaml` 继续是单一来源；POST/PUT 在原子写入前递归校验 DSL、稳定 ID、窗口范围和元数据，并记录操作者。
- 保存与部署分成两个明确阶段；Flink 重启失败沿用既有旧规则恢复链路。
- CEP/基线规则保持只读，避免简化表单静默丢失序列或统计模型字段。

## 验收

- Vue 3 + Ant Design Vue + vue-router 的生产构建通过，React 运行时代码已经删除。
- `/rules` 展示条件摘要；`/rules/:id` 展示条件树与只读 YAML/JSON。
- `/rules/new` 和 `/rules/:id/edit` 能持久化 single_event/window，并拒绝非法字段、空集合、越界窗口、路径穿越和修改稳定 ID。
- 告警、案件、数据源、关键度和用户不再把创建表单堆在列表尾部。
- SOAR 使用 Vue Flow 的输入/输出 Handle 连线，Start/End 明确并校验未闭合路径。
