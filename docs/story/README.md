## Story 粒度与生命周期

- **粒度**:单个 Story 控制在"一个迭代(≤3 天)可完成 + 可测试"的规模;**若单 story 明显 >3 天则必须拆分**。
  - **示例(story-01 拆分)**:01a 接入向导·落库 + 数据源列表(可测试);01b 配置生成(story-01 生成 Logstash input、注入 source 标记)+ 生效(校验/重启/重载)。两段各自可测、可独立验收。
- **依赖**:Story 间依赖在元信息里标注(MVP 是 01/02,后续依赖接入闭环)。
- **生命周期**:草稿 → 评审中 → 已批准 → 已实现(状态在元信息维护)。

## 与其他文档的关系

- **产品设计**:08(总览)/ 07(接入模块)是 Story 拆分的依据。
- **技术设计**:06 及后续围绕模块的技术设计,为 Story 的实现细节提供参考。
- **实现**:每个 Story 批准后进入前后端并行开发(骨架已就绪)。
