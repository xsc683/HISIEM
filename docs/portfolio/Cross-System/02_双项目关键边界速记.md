# 双项目关键边界速记

> **面试前 10 分钟复习这一份。** 只放**真正不能说错**的边界。
> 每一项只有四项：定义 / 区别 / 项目实例 / 一句话记忆。**不要在这里读新知识。**

---

## 一、项目级边界

| 边界 | 区别 | 项目实例 | 一句话记忆 |
|---|---|---|---|
| **HISIEM vs Copilot** | HISIEM = 安全平台（数据/检测/告警/案件/**执行真相**）；Copilot = 决策层（调查/证据/建议/**不越权**） | 两个仓库，一个系统，按权限边界切 | **平台管执行真相，Agent 管调查与建议** |
| **Data Plane vs Control Plane** | 数据面=吞吐优先（事件时间、幂等收敛）；控制面=事务优先（案件、执行状态） | 数据面 Logstash→Kafka→Flink→ES；控制面 Spring Boot→PostgreSQL | **正确性模型不同，所以拆开** |

---

## 二、Flink 时间语义

| 边界 | 区别 | 项目实例 | 一句话记忆 |
|---|---|---|---|
| **Event Time vs Processing Time** | 事件时间=记录内部时间戳（**可复现**）；处理时间=机器墙钟（**不可复现**） | 窗口/CEP/基线用事件时间；**两个抑制器用处理时间** | **检测看事件时间，限流看墙钟** |
| **Watermark vs Allowed Lateness** | Watermark 控制**窗口初次触发前**的等待（影响延迟）；allowed lateness 保留**已触发**窗口状态以便修正（影响状态+可修订性） | 有 `forBoundedOutOfOrderness(10s)`；**没有 allowedLateness** | **乱序=等待，lateness=修正。本项目只有前者** |
| **Watermark vs Checkpoint** | Watermark=事件时间**进度**（瞬态、不存储）；Checkpoint=容错**状态快照**（持久化） | `forBoundedOutOfOrderness(10s)` vs `enableCheckpointing(..., EXACTLY_ONCE)` | **一个管"能求值了吗"，一个管"从哪恢复"** |
| **Idleness vs 每-key 机制** | idleness 作用在**输入分区/通道**，不是 key | `withIdleness(60s)` 在分配算子上 | **管通道，不管 key** |

## 三、投递与可靠性

| 边界 | 区别 | 项目实例 | 一句话记忆 |
|---|---|---|---|
| **Exactly-Once State vs At-Least-Once Delivery** | 前者=算子状态一致快照 + source offset 提交；后者=已交给 sink 的记录可能重复 | checkpoint `EXACTLY_ONCE`；Kafka sink `AT_LEAST_ONCE` | **状态 exactly-once，投递 at-least-once，靠确定性 id 收敛。不叫端到端 exactly-once** |
| **Lease vs Fencing Token** | 租约界定**时间窗口**；fencing token 提供**可拒绝性**（暂停的持有者过期后仍会写） | SOAR 引擎 `requireLease` + `SoarLeaseLostException` + `fencingToken()` | **租约管时间，fencing 管拒绝** |
| **Outbox vs 分布式事务** | Outbox = at-least-once + **因果关联** + 最终一致；2PC = 强一致 | `case_mirror_outbox`(V7) / `lifecycle_outbox`(V19) | **发布是提交的后果，不是第二次独立动作** |
| **确定性 id vs UUID** | 业务身份纯函数→重放**覆盖同一文档**；UUID→每次发射都是新文档 | `sha1(rule_id \| entity \| @timestamp)` + ES `_update` | **id 按业务身份算，重放就覆盖** |

## 四、Agent 与知识

| 边界 | 区别 | 项目实例 | 一句话记忆 |
|---|---|---|---|
| **ToolResult vs Evidence** | 工具返回是**数据**；Evidence 是**只有 grounded 成功才产出**的事实 | 类型化失败 → **零 Evidence** | **工具挂了 ≠ 没有发现** |
| **Knowledge vs Platform Fact** | 知识=**支持性上下文**；平台事实=观测到的事实 | 前端用不同标签渲染；**纯知识不能形成确定性结论** | **知识能解释，不能授权** |
| **Discovery vs Admission vs Selection** | 发现=server 声称（**不可信**）；准入=本地**手写**声明；选择=只读+已准入 | 四个模型可选只读工具；未准入的工具不可选 | **描述是提示面，所以描述要自己写** |
| **Model 能做什么 vs 不能做什么** | 能：提议、调用只读工具、组织证据；**不能**：授权、执行、声明租户 | 四个模型可选只读工具 + 一个系统控制工具 | **模型只能提议** |

## 五、权限链（最核心的一段）

| 边界 | 区别 | 项目实例 | 一句话记忆 |
|---|---|---|---|
| **Finding vs Verdict** | Finding=模型派生的发现；Verdict=调查结论 | `MALICIOUS / BENIGN / INCONCLUSIVE` | **都是模型侧的建议，不是判定** |
| **Agent Verdict vs Analyst Disposition** | 前者=建议；后者=**人的判定** | 独立持久化字段 | **建议 ≠ 判定** |
| **Verdict vs Response Proposal** | 结论是"发生了什么"；提案是"建议做什么" | 独立聚合，响应生命周期独立于调查 | **结论不自动变成动作** |
| **Policy vs Human Approval** | Policy=**规则应用**（系统、确定性）；Approval=**同意**（人） | `DENY \| REQUIRE_APPROVAL` vs `APPROVE \| REJECT` | **规则 ≠ 同意；DENY ≠ REJECT** |
| **Approval vs Execution** | 审批授权的是**意图**；执行发生在 HISIEM | Durable Command + Outbox | **批准不等于执行** |
| **Submission vs Execution Success** | 提交=我交出去了（**不含结果声明**）；执行=它真的发生了什么 | 两套独立状态机 | **没有任何提交状态的值意味着成功** |

## 六、真相边界

| 边界 | 区别 | 项目实例 | 一句话记忆 |
|---|---|---|---|
| **LangGraph Checkpoint vs Domain Truth** | checkpoint=图恢复的**工作内存**；domain=**业务真相** | 两个 schema，两个迁移所有者；**冲突时 Domain 赢** | **checkpoint 管"图从哪继续"，Domain 管"调查是什么"** |
| **Telemetry vs Business Truth** | 遥测是旁路；**没有业务路径读 span** | 停掉 Collector → 持久化业务结果**完全相同** | **丢遥测不改变业务结果** |
| **Frontend vs Authority** | 前端只**派生展示**，不发明状态 | `WORKSPACE_INVENTED_AUTHORITY` 是硬门禁 | **服务端刷新获胜** |
| **Copilot belief vs HISIEM Execution Truth** | Copilot 有"我提交了什么"的**信念**；HISIEM 有"发生了什么"的**记录** | `XP-AUTH-005` runtime-integrated | **HISIEM 赢。这是唯一一条"等于"** |

## 七、权限链条（必须一口气说出）

```text
Model proposes  →  Policy constrains  →  Human authorizes
Durable command records intent  →  HISIEM executes  →  Copilot observes
```

**权限边界的位置：在"结论"与"策略"之间。**
```text
线以上：受模型影响（Tool / Evidence / Finding / Verdict / Proposal）
线以下：确定性（Policy）、人工（Approval）、持久化（Command）、观测（Execution Truth）

→ 从模型输出到副作用之间，不存在代码路径。
```

## 八、五条跨系统边界

```text
① Data Boundary            谁拥有哪份数据
② Trust Boundary           什么内容不可信（MCP 内容 / 检索结果 / 工具返回）
③ Authority Boundary       谁能授权（结论与策略之间）
④ Durability Boundary      什么能扛住重启（批准与提交之间）
⑤ Execution Truth Boundary 谁说了算（HISIEM）
```

**口诀：**
```text
数据分家，内容不信，权限在人，命令落库，结果看平台。
```

## 九、绝对不能说错的 8 句话

```text
❌ 端到端 exactly-once                    → ✅ 状态 exactly-once / sink at-least-once / 确定性 id 收敛
❌ 处理迟到数据（HISIEM）                  → ✅ 只在 10 秒容差内吸收乱序；无 allowedLateness、无 side output
❌ 单事件规则用 watermark                  → ✅ 单事件消费 parsed，不走 watermark；抑制是处理时间
❌ 知识子系统对模型不可达（DRIFT-001）      → ✅ 四个模型可选只读工具，含两个 knowledge 工具
❌ 语义检索质量高                          → ✅ 机制可讲，质量未验证；产物标 PLUMBING_ONLY
❌ 我们防住了提示注入                      → ✅ 架构约束了爆炸半径；注入能影响结论，不能授权
❌ 审批通过就执行了                        → ✅ 审批授权的是意图；执行在 HISIEM；结果由 HISIEM 观测
❌ 285 条架构不变量                        → ✅ 285 个测试用例（多为逐模块参数化）
```
